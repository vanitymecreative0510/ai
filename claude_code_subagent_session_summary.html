Part 1：なぜ1つの会話で色々頼むとAIの精度が下がるのか？（Microsoft最新研究）

📉 Context Rot（コンテキストの腐敗）とベンチマークの罠

AIに入力する文章量が増えるほど性能が落ちる現象は「Context Rot（コンテキストの腐敗）」として知られる。さらに重要な点として、各社が発表するモデルのベンチマークは基本的に「1回の指示（シングルターン）」で測定されているが、実務では1つのセッションで何度も条件を足したり別の仕事を頼んだりしている。

🔬 Microsoft論文（2026年7月）が検証した「3種類の意図の変化」

① Reveal（開示・後出し追加） 影響：小〜中

後から条件を足す指示。
例：提案書を作らせた後に「相手は製造業のお客さんです」「予算は100万円です」と後出しで条件を追加する。

② Revise（修正・条件変更） 影響：中

途中で条件を覆す指示。
例：最初は「製造業・予算100万」と言ったのに、途中で「サービス業でした」「予算300万でした」と変更する。

③ Switch（タスクの切り替え）⚠️ 影響：極めて大

途中で別の仕事を頼む指示。
例：提案書を作らせた後、同じセッションで「次はこれを先方に送るメールを作って」と仕事を切り替える。

🚨 結果1：最新モデルでも最大約18〜20%精度低下（04:47〜）

3種類の変化を2回ずつ（計6回）入れると、最新のGPT-5.5クラスでも全試験で精度が落ち、特定の試験では-18%（約20%近く）低下。最高位モデル（Opus等）を使っていても、雑多な会話の中で使うと下位モデル（Sonnet等）のシングルターンより低い精度になる。

🚨 結果2：「途中でSwitch＋その後に修正」が最悪（07:56〜）

会話の「一番最後」に別タスク（Switch）を頼むならまだ耐えられるが、「途中で別タスクに切り替えた後、さらに日程追加や宛先変更（Reveal/Revise）を重ねる」と、切り替え前の何を引き継ぐべきかAIが混乱し、精度が著しく崩壊する。

⚠️ 結果3：プロンプトによる要約指示は劇的には効かない（09:25〜）

「これまでの条件や目標をAI自身に整理・要約させる」プロンプトを入れても精度はわずかに改善する程度で、タスクによっては逆に下がることもあり、根本解決にはならない。

⚠️ 結果4：難しいタスクほど劣化幅が激しい（10:00〜）

簡単なタスクよりも、論理的思考や高度な処理が必要な難しいタスクほど、意図の変化が重なった時の精度の落ち幅が大きくなる。

Part 2：サブエージェントで「作成」と「検証」を分業する技術

★ URL指定位置 (17:17 / 1037秒) を含むパート

📌 原則：「1タスク＝1セッション」とサブエージェントの役割

基本は仕事が変わるたびに「新規作成」で別セッションを開くこと。ただし「Aの作業中に文脈を活かしつつBも頼みたい」「新規セッションにファイル書き出しで引き継ぐのが面倒」という時は、メインエージェントから別のAI（サブエージェント）を呼び出して分業させる。

🔑 重要テクニック：「会話をフォークしない」で起動する（14:55〜）

サブエージェントには「①メインの会話履歴を丸ごと引き継ぐ（フォークする）」と「②必要な文脈だけ指示として渡す」の2パターンがある。論文の通り雑多な会話履歴を引き継ぐと精度が落ちるため、「フォークしないで（独立した）サブエージェントを起動して」と指示する方がシングルターンに近い高精度が出る。

🎯 実演①：資料作成後の「ファクトチェック＆レイアウト点検」並列分業（15:59〜18:00）

17:17 (1037秒) 指定箇所

資料を作ったメインAI自身に「これどう？」と聞いても「満点じゃ！」と甘く評価してしまう。そこで「作る役」と「見る役（検証役）」のAIを完全に分ける。

💬 実演で使われたプロンプト：
独立したサブエージェントを起動して、こちらの資料のファクトチェックや、レイアウト・改行などが読みやすいかをチェックして、必要に応じて修正指示を出してください

👉 17:04〜17:30（指定秒数の挙動）：メインエージェントから「①ファクトチェックを行うサブエージェント」と「②レイアウト・改行の点検を行うサブエージェント」の2つが同時に起動。

👉 各サブエージェントは余計な履歴を持たず「シングルターン」と同じ集中状態で作業するため、メインAIだけでは見落としていた複数の改善箇所を発見し、そのフィードバックを元にメインAIが自動で高品質に修正を完了した。

🌙 実演②：寝る前に仕込む「自動検証・改善ループ」プロンプト（18:01〜19:22）

1回の指示で作成〜検証ループまで自動化

成果物を見てから手動でサブエージェントを呼ぶのではなく、最初のプロンプトに「作成＋サブエージェント検証ループ」をセットで組み込む手法。

私はもう寝ます。〇〇というタスクをやっておいて、その後サブエージェントを起動してフィードバックループを回すことを最高の品質が出るまで繰り返しやっといてください。おやすみなさい。

💡 ポイント：「私はもう寝ます」と書くことで、AIが気を遣って途中の確認質問で止まらずに最後まで自律的に回し切ってくれる（トークンは多く消費するが、朝起きると高品質な成果物が完成している）。

Part 3：Claude Desktopの「セッション管理機能」で複数タスクを並列統括

🖥️ サブエージェントと「サブセッション」の違い（19:23〜）

通常のサブエージェントはバックグラウンドで動くため「今何をやっているか見えにくい・直接追加指示を出しにくい」という弱点がある。
一方、Claude Desktop（デスクトップアプリ版）のセッション管理機能を使うと、左サイドバーに独立した「サブセッション」が自動生成され、進捗の目視確認や個別指示が自在に行える（CLI版ではできないUIならではの強み）。

🌐 実演：英語・中国語・フランス語版の並列作成（20:00〜22:15）

  • 一括起動：メインセッションで「この資料を英語・中国語・フランス語にするセッションをそれぞれ独立で立ち上げて作っておいて」と指示。
  • 進捗確認：作業中もメインセッションと会話でき、「今どんな進捗？」と聞けば3つのサブセッションの状況を集約して報告してくれる。
  • 個別への追加指示：メインから「中国語版は5枚にしておいて」と頼めば、中国語のサブセッションに自動でメッセージが送られて作業が継続される。

🧹 サイドバーを綺麗に保つ「自動アーカイブ」設定（22:49〜）

サブセッションを10個・20個と立ち上げると左サイドバーが散らかってしまうため、Claude Codeのメモリに「タスクが終わったセッションはアーカイブするように覚えておいて」と記憶させておく。作業完了時に「アーカイブしますか？」とボタンが出るようになり、ワンクリックで左サイドバーから綺麗に収納できる。

🚀 最新トレンド：OpenAI Dots と Claude Duet（23:45〜）

OpenAIの「Dots」や、Anthropicが米国でリサーチプレビュー提供中の「Claude Duet」も同じく、「人間が話す窓口は1つのAIだけで、裏側の複数セッション作成・管理はAIが担う」設計になっている。人間に代わってAIにセッション管理を任せるのが今後の主流トレンド。

❌ パターン1：1つのセッションで全部やる（非推奨）

提案書作成の途中でメール作成（Switch）を頼み、さらに条件修正（Revise）を重ねると、最新モデルでも最大約20%精度が低下。最上位モデルが下位モデル並みに劣化する。

⭕ パターン2：サブエージェントで分業（検証・品質向上に最適）

会話履歴を引き継がず（フォークせず）に独立したサブエージェントを起動し、ファクトチェックやレイアウト点検を別AIに担当させる。寝る前の自動改善ループにも最適。

🌟 パターン3：Claude Desktopのサブセッション管理（並列作業に最適）

メインセッションが左サイドバーに複数のサブセッション（英語・中国語・仏語版など）を立ち上げて統括。人間は1つの窓口と話すだけで進捗確認・追加指示・完了後のアーカイブまで完結する。
