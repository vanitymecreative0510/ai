序章：なぜ同じClaude Codeなのに「超天才」と「超バカ」に分かれるのか？

👶 新規スレッド ＝「赤ちゃんの誕生」

Claude Codeは記憶容量（コンテキスト）に限りがあるため、新しいスレッドを立てるたびに「新しく生まれ直す」のと同じ状態になる。生まれた周りに「しょうもない相談の名残」「会社と無関係な情報」「ダメな例」が散乱していると、それを吸収してバカな出力になる。

⚡ モデルの差ではなく「作業場の設計」の差

「環境設定が整った旧モデル（GPT-4）」と「環境が散らかった最新モデル」なら、前者の方が圧倒的に賢いアウトプットを出す。100レベルのミュウツーを持っていても「なきごえ」しか指示できなければ意味がないのと同じで、作業場の設計と仕組みの理解がすべてを決める。

Part 1：Claude Code 直近アップデート「仕事で使える新機能」7選

★ URL指定位置 (03:41) を含むパート
① 右側「セッションレール」の新設 02:00〜

画面右側にセッションレールが登場し、以前バラバラだったフォルダ表示等が集約。以下の3つがリアルタイムに可視化される：

  • 環境（Environment）：今どこで動いているか
  • コンテキスト（Context）：上限100万トークン中、何%がどこに使われているか
  • コネクター（Connectors）：外部連携の接続状態
② 無関係なタスク依頼時の「3択制御」🎯 03:36〜 (指定位置)

スレッド内で急に文脈と無関係な話を振った際、AIが「今その話関係ないじゃん」と判断して以下の3つの挙動を設定できるようになった：

  1. 質問する：「関係ないけど今ここでやりますか？」と確認
  2. そのまま実行：現在のセッション内でそのまま処理
  3. 別セッション開始：コンテキスト汚染を防ぐため自動で新規セッションへ分岐

⚠️ みかみ氏の警告：最近のAIは2択で質問してくるが、人間は文字を読まずに「おすすめ」を思考停止でポチポチ選びがち。安易な2択に流されると人間側が劣化するので要注意。

③ 入れ子のセッション（子タスク機能） 05:12〜

親セッションの下に階層構造で「子タスク（入れ子のセッション）」を起動可能。1つのスレッドで雑多な議論をすると会話がバカになるため、親のコンテキストを引き継ぎつつ子タスクに切り出して実行し、クリック1つで親子の画面を行き来できる。

④ BTW（By The Way / サイドチャット） 06:15〜

メインの作業スレッドを邪魔せずに、「ところで（BTW）これ本筋と関係ないけど聞きたい」「なんでこの図いまいちなの？」といった横道の疑問をサイドチャットとして即座に質問できる機能。

⑤ 動画再生 ＆ 別ウィンドウ切り離し 06:51〜

従来アプリ内で再生できなかった動画ファイルの直接再生に対応。さらにチャットを別ウィンドウで開く機能が追加され、重い処理が動いているスレッドを別窓で並べて監視し、ワンクリックでメイン画面に戻せる。

⑥ やることリスト（ToDo）の常時可視化 07:22〜

「あと何したらいいか考えて」と指示すると、進行中のタスクリストを常時表示。「タスクは情報の圧縮効率が最も高いフォーマット」であり、上司（人間）が「AIの進め方が合っているか」を一目で監督できる。

🔮 みかみ氏の予言：「公式が進化して取り込む領域」は絶対に自分で作るな

かつてコンテキスト可視化ツールを必死に自作していた人たちは、今回の公式アップデート（セッションレール）ですべて不要になった。AIツールの進化方向を見極め「そこは作らない」と意思決定することが重要。次にClaude Code公式が確実に取り込むと予言しているのは、アドネス社が独自運用している「判断シート（部下が上司に『この点についてご意見を伺いたく』と論点を整理して決済を仰ぐ仕組み）」。

Part 2：自分のClaude Codeを「超天才」に覚醒させる『7つの型』

※ 특히 型1〜型3 が本質

単なる CLAUDE.md の小手先プロンプトではなく、「成果が出る人間の脳みその動かし方」をそのままClaude Codeの作業場に再現するための7つの設計ルール。

【型1】覚えておかない（記憶の完全デジタル化と「ゴール起点」の統合）

12:15〜18:55

「自分しか持っていない記憶（紙のメモや頭の中だけの構想）」をゼロにし、自分の脳内とClaude Codeがアクセスできる情報を8〜9割イコールにする（紙に書いた場合も即スマホで撮影してAIに送る）。

📂 2つの記憶の置き場 ・ローカル（作業場）：日誌（Dailyログ）、議事録、AIのローカルメモリ
・クラウド（Addness）：親ゴール、子ゴール、プロジェクトメモリ
🔗 なぜObsidianや標準メモリでは不十分か？ 単なるベクトル検索やリンク付けは「文字列が検索されるだけ」。人間の脳は「売上を上げる（ゴール）」に対して過去の別事業やサッカーの経験（点と点）が繋がる。ゴールに記憶と行動履歴を紐づける基盤が必要。

【型2】説明し直さない（前提・背景を1つも取り漏らさない導線設計）

18:56〜22:32

サッカーの試合に「水筒を1本忘れる」だけで致命傷になるように、仕事も前提が1つ抜けるだけで全く別物になる。しかし人間はAIに「こうですね」と言われると流され、抜けている前提を毎回説明し直すのは不可能。

  • 雑に頼んでも「ゴールと理想」「過去の経緯」「現在の議論」「関連資料の格納場所」をAIが自動で取りに行くよう CLAUDE.md と記憶基盤を噛み合わせる。
  • YouTubeのカット編集履歴や数値データ、個人の感覚まで紐づけて蓄積することで、AIが「データ上はこうなので、この改善案もあります」と自分の感覚の抜けを補う壁打ちパートナーに進化する。

【型3】コミュニケーションを楽にする（判断シート＆ビジュアル提示）

22:33〜23:16

チャット画面の長文テキストを読むのは人間の認知負荷が高い。優秀な部下が「図解」や「選択肢」を持ってくるように、AIとの対話フォーマットを規定する：

  • 質問がある時は「判断シート」の顔つきで論点と選択肢をわかりやすく提示させる。
  • 変更点や構成案はHTMLシート等でビジュアルに比較表示させ、「B案ベースで上だけA案を混ぜて」と直感的に指示できるようにする（Claude Code標準の簡易Visualize READMEより見やすい独自シートを出力させる）。

【型4】余計な言葉を使わせない

23:17〜

AI特有の気取った比喩（例：「誰の頭を鳴らすか決める」など意味不明な表現）や無駄なオウム返しを徹底禁止。「誰に見せる動画にするか決める」のような人間にとって自然で直接的な表現に矯正し、モデル更新のたびに微調整する。

【型5】勝手にスコープを広げさせない

24:11〜

Claude Codeは気を利かせて頼んでもいない周辺タスクまで手を広げ、全体をぐちゃぐちゃにする癖がある（Codexは頼んだことだけスパッとやる）。「下手にやることを増やすな、指定スコープだけに集中しろ」と厳格に縛る。

【型6】判断すべき時だけ止まり、最後までやり切る

24:34〜

丁寧ぶって些細なことを毎回確認して止まるのを禁止。本当に人間の意思決定が必要な分岐点（判断シート）以外は、ビビらずに頼んだゴールまで一気に完走させる。

【型7】全部読ませない（コンテキスト絞り込み）

24:56〜

すべての情報を無差別にAIに読ませると、トークン効率が悪化するだけでなくノイズで失敗確率が跳ね上がる。「余計なものは見なくていい」と参照範囲をキュッと絞るルーティングを行う。

Part 3：実演公開された「超天才の記憶基盤」とテンプレートの全貌

🎯 1. ゴール階層ツリー

「2031年 ARR 3兆円」という頂点ゴールから、「2027年4月1日の状態」→「2026年10月（今月）誰が・どこで・何を・何の目的でやっているか」までが一気通貫で構造化され、すべての記憶がこのゴールツリーに紐づく。

📚 2. 部署別ナレッジ（347件）

「いつ・どこで・誰が・何のために・どういう時はどう動くか」という判断ルールや業務ナレッジが部署ごとに347件体系化されており、タスクに応じて必要なナレッジだけが自動で呼び出される。

📊 3. 全社KPIマップ（627種類）

社内で追っている627種類の重要数値（何を・どこで計測し・どう繋がっているか）をClaude Codeがすべて把握。YouTubeのリスト単価が高ければ、マーケや営業のAIが検知して優秀な営業担当を自動アサインする等の連携が可能に。

⚖️ 徹底比較：「超バカになるClaude Code」vs「超天才に覚醒したClaude Code」

比較項目 ❌ 一般ユーザーの「超バカ」な状態 ⭕ みかみ流「超天才」に覚醒した状態
1. スレッド環境・記憶 無関係な雑談やダメな例が混재。紙のメモや個人の頭の中にしか前提がなく、毎回記憶リセット。 無関係な話は別セッション/入れ子/BTWへ分離。ローカル日誌＋クラウドのゴールツリーに記憶を8〜9割デジタル統合。
2. 前提の共有方法 毎回プロンプトで背景を説明し直すか、前提が抜けたままAIの「こうですね」に流されて失敗する。 CLAUDE.md と記憶基盤が連動し、ゴール・過去経緯・627種のKPI・347件のナレッジを自動参照。
3. 対話・確認スタイル 長文テキストを読むのが苦痛で、AIが出す安易な2択の「おすすめ」を思考停止でポチポチ選ぶ。 ビジュアル図解と「判断シート」で論点を可視化。「B案ベースで上だけA案」など直感的に意思決定。
4. 言葉遣い・スコープ 気取ったAI構文やオウム返しが多く、頼んでもいない周辺作業まで勝手に広げてぐちゃぐちゃになる。 不自然な比喩やオウム返しを禁止。指定スコープだけを厳守し、判断ポイント以外は最後まで一気に完走。
5. コンテキスト管理 ファイルを全部読ませてトークンを浪費し、ノイズ過多で精度が低下する。 セッションレールで100万トークンの消費を監視しつつ、必要な情報だけを絞って読ませる（型7）。
① スレッド環境・記憶の持ち方
❌ Before（ダメな状態）：
1つのスレッドに無関係な話を混ぜて汚染。大事な前提が紙のメモや自分の頭の中にしかなく、毎回リセットされる。
⭕ After（覚醒した状態）：
入れ子セッション・BTWで文脈を分離。ローカル（日誌）とクラウド（ゴール基盤）に全記憶をデジタル統合。
② 前提の共有・説明コスト
❌ Before（ダメな状態）：
「水筒を忘れる」ように重要な前提が抜け落ち、AIの「こうですね」に人間が流されて微妙な成果物ができる。
⭕ After（覚醒した状態）：
雑に頼んでも CLAUDE.md 経由でゴール・過去経緯・KPI・ナレッジを自動で引きずり出し、前提を1つも漏らさない。
③ 対話・意思決定のやり方
❌ Before（ダメな状態）：
長文テキストを読むのがしんどく、AIが聞いてくる2択の「おすすめ」を思考停止で連打してしまう。
⭕ After（覚醒した状態）：
「判断シート」とビジュアル比較図で提示させ、本当に人間が決めるべき分岐点だけ直感的に判断する。
④ スコープ管理・コンテキスト効率
❌ Before（ダメな状態）：
頼んでいない作業まで勝手に広げて破綻。ファイルを全部読ませてトークンと精度を浪費する。
⭕ After（覚醒した状態）：
余計な言葉・スコープ拡大を禁止し、必要なファイルだけをキュッと絞って読ませて最後まで完走させる。
